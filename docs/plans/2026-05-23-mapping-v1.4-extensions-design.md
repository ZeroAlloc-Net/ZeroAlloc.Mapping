# ZeroAlloc.Mapping v1.4 — design

**Date:** 2026-05-23
**Scope:** Three backlog items promoted from `docs/backlog.md` for the
v1.4 release. All opt-in/additive — no v1.0/1.1/1.2/1.3 surface change.

## Items

| ID | Title | Surface |
|---|---|---|
| B3 | `IQueryable` projections | `[Map<TSrc, TDst>(Projection = true)]` → emits `public static Expression<Func<TSrc, TDst>> Projection` on the declaring class |
| B6 | Reference handling / cycle detection | `[Map<TSrc, TDst>(CycleSafe = true)]` → emits a tracker-threading recursive overload that handles back-refs via a `Dictionary<object, object>` cache |
| B11 | `UseDeepCloning` mode | `[Map<TSrc, TDst>(DeepClone = true)]` → emits per-property literal copy for every reachable reference type where no explicit nested `[Map<,>]` declaration exists |

Working notes captured during brainstorming live at
[`2026-05-23-mapping-v1.4-decisions-log.md`](2026-05-23-mapping-v1.4-decisions-log.md).
That file records the considered-and-rejected alternatives for each
decision; this document is the canonical specification.

**Out of scope for v1.4:** B7 (private member mapping). The other open
backlog item was explicitly deferred as out-of-scope-by-design — it
remains on the backlog as the deliberate policy statement.

## Goals

- **Each feature opt-in.** v1.3 mapping behaviour unchanged for users
  who don't touch the new properties. Default values on the three new
  `[Map<,>]` flags keep existing emit byte-identical.
- **No reflection, no runtime type lookup.** All decisions made at
  generator time; emit is plain C#.
- **Zero-allocation paths preserved by default.** Users opt into the
  allocation cost when they ask for `CycleSafe = true` (tracker
  dictionary) or `DeepClone = true` (per-property copies). The
  default `Map(src)` path remains zero-alloc for users who don't opt
  in.
- **Fail loudly, not silently.** Every combination the generator
  can't honour fires a compile-time diagnostic. The four new
  diagnostics (ZAMP017–ZAMP020) cover the cases that can't translate
  to EF Core, that have non-CycleSafe gaps, that touch uncloneable
  types, and that cycle through type graphs without cycle handling.
- **Reuse existing machinery.** No new architectural layer — extend
  `MapEmitter`, `MapperDiscovery`, `MappingDiagnostics`, and
  `MappingGenerator`. One new helper emitter
  (`ProjectionExpressionEmitter`) for the LINQ-expression-tree path.

## Decisions

### 1. B3 — `IQueryable` projection

#### 1.1 Surface

```csharp
public sealed class MapAttribute<TSrc, TDst> : Attribute
{
    // ... existing properties ...
    public bool Projection { get; init; } = false;
}
```

When `Projection = true`, the generator emits an additional static
member on the declaring class:

```csharp
public static class OrderMapper
{
    public static OrderDto Map(Order src) { /* runtime body */ }

    public static System.Linq.Expressions.Expression<System.Func<Order, OrderDto>> Projection { get; } =
        src => new OrderDto
        {
            Id = src.Id,
            Name = src.Name,
            // ... every member mapped explicitly ...
        };
}

// Consumer:
db.Orders.Select(OrderMapper.Projection).ToList();
```

The expression tree is built once at class init via a static
property initializer. The static `Expression<Func<...>>` literal is
the standard LINQ-projection idiom that EF Core's translator
consumes — no AutoMapper-style `IQueryable.ProjectTo<T>()` extension,
which doesn't fit the package's static-mapper-class pattern.

#### 1.2 Nested mappings inline silently

When the outer mapping references a nested type with its own
`[Map<,>]`, the generator inlines the nested mapping body into the
outer `Projection` expression:

```csharp
// Given:
//   [Map<Order, OrderDto>(Projection = true)]
//   [Map<Customer, CustomerDto>]    (no Projection flag — auto-inline)
// Emit:
src => new OrderDto
{
    Customer = new CustomerDto { Name = src.Customer.Name, ... },
    ...
}
```

The nested mapping does NOT need its own `Projection = true`. EF
Core can't translate cross-mapper calls (`CustomerMapper.Map(...)`
kills SQL generation), so inlining is the only viable emit. The
metadata the generator needs is already collected for the runtime
emit; reusing it is free.

#### 1.3 Forward direction only

`[Map<TSrc, TDst>(Projection = true)]` emits a `Projection`
property going `TSrc → TDst` only. `[ReverseMap]` does NOT
automatically project the reverse direction — the user must
declare `[Map<TDst, TSrc>(Projection = true)]` explicitly to get
a reverse `Projection`.

#### 1.4 Feature incompatibility — ZAMP017

`[Map<,>(Projection = true)]` is incompatible with three features
because EF Core's LINQ translator can't handle them. The generator
fires `ZAMP017` (Error) when any of the following applies to the
mapping itself OR to any transitively-inlined nested mapping:

- `[MappingHook]` methods (B4) — user method calls.
- `[MappingCulture]` parsing (B9) — `IFormatProvider` lookups.
- Polymorphic dispatch via `[PolymorphicMap]` (B2) — runtime type
  switching.

User remedy: remove the incompatible feature OR remove
`Projection = true`.

### 2. B6 — cycle-safe mapping

#### 2.1 Surface

```csharp
public sealed class MapAttribute<TSrc, TDst> : Attribute
{
    // ... existing properties ...
    public bool CycleSafe { get; init; } = false;
}
```

When `CycleSafe = true`, the generator emits TWO methods on the
declaring class:

```csharp
public static OrderDto Map(Order src)
{
    var __tracker = new System.Collections.Generic.Dictionary<object, object>(
        System.Collections.Generic.ReferenceEqualityComparer.Instance);
    return Map(src, __tracker);
}

internal static OrderDto Map(Order src, System.Collections.Generic.IDictionary<object, object> tracker)
{
    if (tracker.TryGetValue(src, out var __cached)) return (OrderDto)__cached;
    var dst = new OrderDto();
    tracker.Add(src, dst);                 // register BEFORE walking children — handles self-cycle
    dst.Id = src.Id;
    dst.Customer = CustomerMapper.Map(src.Customer, tracker);    // tracker threaded
    // ...
    return dst;
}
```

Key shape:

- Public entry `Map(src)` allocates a fresh tracker per call. No
  user-visible API change on the existing call site — the existing
  signature works exactly the same way, just with one allocation up
  front.
- Internal recursive `Map(src, tracker)` is the cycle-safe body. It
  checks the cache, registers the new destination BEFORE walking
  children (so self-cycles like `parent.Children[0].Parent` resolve
  to the original `dst`), then walks children with the tracker
  threaded through.
- `ReferenceEqualityComparer.Instance` is the cache key comparer —
  identity-based, not value-based.

#### 2.2 Transitive enforcement — ZAMP018

Every nested mapping reachable from a `CycleSafe = true` mapping
must ALSO declare `CycleSafe = true`. Otherwise: `ZAMP018` (Error).

User remedy: annotate every type in the graph that participates in
cycle-safe mapping. The diagnostic message points at the
non-CycleSafe nested mapping the outer mapping is trying to call.

Rationale (vs. auto-propagation): the package's family idiom favours
explicit-over-magic. The user can look at a single `[Map<,>]`
declaration and see whether it's CycleSafe. Auto-propagation (a la
B3's auto-inline) is appropriate for emit-time transformations
that don't change runtime behaviour; cycle handling DOES change
runtime behaviour (allocation, recursive structure) so explicit
opt-in is worth the bookkeeping.

### 3. B11 — DeepClone mode

#### 3.1 Surface

```csharp
public sealed class MapAttribute<TSrc, TDst> : Attribute
{
    // ... existing properties ...
    public bool DeepClone { get; init; } = false;
}
```

When `DeepClone = true`, the generator walks the reachable-type
graph at compile time. For every reference-typed property of TSrc
where NO explicit nested `[Map<,>]` declaration exists, the
generator emits a literal per-property copy:

```csharp
// Given:
//   [Map<Order, OrderDto>(DeepClone = true)]
//   (no explicit [Map<Tag, TagDto>] — Tag is auto-cloned)
//   (no explicit [Map<Customer, CustomerDto>] — Customer is auto-cloned)
// Emit:
dst.Tags = new List<Tag>(src.Tags.Count);
foreach (var __item in src.Tags)
    dst.Tags.Add(new Tag { Name = __item.Name, Id = __item.Id, ... });

dst.Customer = new Customer { Name = src.Customer.Name, ... };
```

Explicit nested `[Map<,>]` declarations always win — they remain the
family idiom for mapping between distinct DTO shapes. `DeepClone`
only kicks in for types where the user did NOT declare an explicit
nested mapping (e.g., a collection of the same type, a back-pointer
to the source type itself, a shared library type the user doesn't
own).

Recursion is fully transitive: Order → Customer → Address emits
clone code for all three types. Value-typed properties (primitives,
structs) are bit-copied via standard assignment; only reference
types descend.

#### 3.2 Cloneability audit — ZAMP019

For every reachable type, the generator verifies it can be cloned
via a public parameterless ctor + settable / init-only members.
Types that can't be cloned trigger `ZAMP019` (Error):

- No public parameterless ctor AND no usable primary-constructor.
- All members are `get`-only and not init-only.
- Required init members the generator can't supply at construction.

User remedy: add an explicit nested `[Map<,>]` declaration at the
problem type to take over the clone explicitly, OR change the type's
shape so it can be cloned automatically.

This is the package's response to the original deferral reasoning:
"opaque deep-cloning makes generated code hard to audit." The clone
emit is per-property and visible in the generated source; the
diagnostic catches the cases where the generator can't deliver an
auditable clone.

#### 3.3 Type-graph cycles — ZAMP020

If `DeepClone = true` walks into a cyclic type graph (Order →
Customer → Order back-ref), the generator's type-walk would
infinitely recurse at emit time. The generator detects the cycle
and fires `ZAMP020` (Error) when `CycleSafe = true` is NOT also
declared.

User remedy:
- Add `CycleSafe = true` (and propagate per ZAMP018) to enable the
  runtime tracker. The generator's deep-clone walk then threads the
  tracker through nested clones — runtime cycles resolve via the
  cache.
- OR add an explicit nested `[Map<,>]` at the cycle boundary to
  break the recursion at emit time.

When `DeepClone = true` AND `CycleSafe = true` coexist on a cyclic
graph, the emit looks like:

```csharp
internal static OrderDto Map(Order src, IDictionary<object, object> tracker)
{
    if (tracker.TryGetValue(src, out var __cached)) return (OrderDto)__cached;
    var dst = new OrderDto();
    tracker.Add(src, dst);
    dst.Customer = MapCustomer(src.Customer, tracker);    // deep-cloned, tracker-threaded
    return dst;
}

private static Customer MapCustomer(Customer src, IDictionary<object, object> tracker)
{
    if (tracker.TryGetValue(src, out var __cached)) return (Customer)__cached;
    var dst = new Customer();
    tracker.Add(src, dst);
    dst.Name = src.Name;
    dst.LastOrder = Map(src.LastOrder, tracker);           // back-ref — cycle handled by tracker
    return dst;
}
```

### 4. Cross-feature compatibility

All pairwise combinations of `Projection`, `CycleSafe`, and `DeepClone`
are valid. No diagnostic fires for these combinations beyond the four
listed above.

| Combination | Behaviour |
|---|---|
| Projection + CycleSafe | Independent emits. Projection (static expression) doesn't thread a tracker — EF translates to SQL which has no recursion. Runtime `Map(src)` still gets the CycleSafe behaviour. |
| Projection + DeepClone | Projection is deep-clone-by-construction (every property assigned explicitly). DeepClone affects only the runtime `Map` body. Redundant on the Projection side but useful when the user wants runtime deep-clone too. |
| CycleSafe + DeepClone | Exactly the combination ZAMP020 directs users toward. Tracker threaded through every nested clone. |

## New diagnostics

| ID | Severity | Condition |
|---|---|---|
| `ZAMP017` | Error | `[Map(Projection = true)]` uses or transitively inlines `[MappingHook]`, `[MappingCulture]`, or `[PolymorphicMap]` — EF Core can't translate these. |
| `ZAMP018` | Error | `[Map(CycleSafe = true)]` references a nested `[Map<,>]` that is NOT also `CycleSafe = true`. |
| `ZAMP019` | Error | `[Map(DeepClone = true)]` reaches a type the generator can't clone (no public ctor / no settable members / unsupplied required init). |
| `ZAMP020` | Error | `[Map(DeepClone = true)]` walks a cyclic type graph without `CycleSafe = true`. |

## Out of scope

- **B7 (private member mapping).** Remains on the backlog as the
  deliberate policy statement against breaking encapsulation. Not
  shipping in v1.4.
- **`IQueryable<TSrc>.ProjectTo<TDst>()` extension method.** Doesn't
  fit the static-mapper-class pattern. Users compose via
  `db.Orders.Select(OrderMapper.Projection)`.
- **Runtime cycle-detection mode.** Detect-and-throw was explicitly
  rejected — same protection comes from NOT opting into CycleSafe
  (cycles stack-overflow naturally and loudly).
- **`HashSet<object>` tracker variant** for B6.
  `Dictionary<object, object>` with reference equality is the only
  shape, because the graduation signal calls for graph-shaped
  domain (not just cycle detection).

## Backward compatibility

  each defaulting to `false`. Existing v1.3 declarations are

- New `Projection` static property emit, new internal `Map(src,
  tracker)` overload emit, new deep-clone emit subtree — all gated
  on the corresponding opt-in flag. None of them appear in the
  generated source unless requested.
- `PublicAPI.Shipped.txt` untouched. Six new lines in
