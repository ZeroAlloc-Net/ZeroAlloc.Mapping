# Mapping v1.5 — `DeepClone + CycleSafe` full integration (B12)

**Date:** 2026-05-23
**Scope:** Land backlog item **B12** — when `[Map(DeepClone = true, CycleSafe = true)]` is declared, clone the entire reachable graph with runtime cycle resolution that covers *every* type in the graph, not just types with explicit nested `[Map<,>]` declarations.

## Background

`ZeroAlloc.Mapping` v1.4 (PR #17) shipped `B3` (IQueryable projections), `B6` (CycleSafe), and `B11` (DeepClone) together. Post-merge code review surfaced a behavior gap (C-1 in the review): when both `DeepClone = true` and `CycleSafe = true` were set, the `CycleSafe` routing fork won and `DeepClone`'s literal-walk path never activated. Reference-typed properties without an explicit nested `[Map<,>]` were silently *aliased* instead of cloned.

The v1.4 fix was to align the docs with the actual behavior. `B12` was added to the backlog (`docs/backlog.md`) to track the proper integration:

> When both `DeepClone = true` and `CycleSafe = true` are set on a `[Map<,>]`, emit the deep-clone literal walk with the runtime tracker threaded through every nested clone call. Currently the CycleSafe routing fork wins and DeepClone literal walks don't activate.

This design picks **option (a)** from the backlog's "Why deferred" note — merge the walks into a single emit pipeline — by extending `EmitCycleSafeMapPair`'s per-property resolver to delegate to generator-emitted per-type clone helpers when no explicit nested `[Map<,>]` is declared.

## Decisions

### D-1: semantic — full cycle-safe deep clone

`[Map(DeepClone = true, CycleSafe = true)]` means: **clone the entire reachable graph, and every type in that graph participates in runtime cycle resolution.** Reference types without an explicit nested `[Map<,>]` are literal-walked through generator-emitted helpers; those helpers thread the tracker so cycles through any reachable type resolve correctly.

**Considered and rejected:**

- **Hybrid (tracker for explicit nested, plain inline `new T { ... }` for literal-walked types).** Cycles through literal-walked types would NRE / loop. Preserves the silent-misbehavior bug B12 exists to fix.
- **Defer with `ZAMP021` warning + docs-only.** Tells the user to pick one approach. Punts the integration indefinitely; the workaround (declare explicit nested `[Map<X,Y>]` for every reachable type) is too noisy for non-trivial graphs.

### D-2: compile-time constraint — `ZAMP021` on cycles through primary-ctor-only types

The `CycleSafe` shape requires `tracker.Add(src, __new)` *before* walking children: when a child recursively references the parent, the tracker resolves the parent's already-allocated `__new` instead of re-entering. This requires the destination type to allow staged construction — `var __new = new T(); tracker.Add(...); __new.Prop = ...; return __new;` — which works only for types with a public parameterless ctor + settable properties.

For records / immutables (primary-ctor-only), construction is atomic; we can't register a half-built object in the tracker before its children are evaluated.

The generator walks the type graph from each `[Map(DeepClone+CycleSafe)]` declaration's destination type. Reference-typed properties recurse; value types / strings / types with explicit nested `[Map<,>]` stop the walk. For each reachable type:

- **Public parameterless ctor present** → gets a clone helper, fully cycle-safe.
- **Primary-ctor-only AND walk detects a cycle through it** → fire **`ZAMP021`** on the top-level declaration: *"DeepClone + CycleSafe requires public parameterless constructor on `TypeX` (cycle detected from `[Map<Src,Dst>]`). Add a parameterless ctor, declare an explicit nested `[Map<X,Y>]`, or drop `CycleSafe`."*
- **Primary-ctor-only AND no cycle** → emit inline `srcExpr is null ? null! : new T(arg1: ..., arg2: ...)`, no tracker registration, no helper.

This retires the existing `TODO: ZAMP021` comment in `MapEmitter.cs:210` (which had the constraint scoped only to explicit nested mappers — D-2 generalizes it to literal-walked reachable types).

**Considered and rejected:**

- **Hard error on every primary-ctor-only type in the graph (regardless of cycles).** Safest but blocks legitimate cases — a `[Map(DeepClone+CycleSafe)]` over a graph that contains records but happens to have no actual cycles is benign.
- **Soft fallback (use primary ctor without tracker registration, no diagnostic).** Resurrects the silent-misbehavior bug.

### D-3: emit shape — shared per-type helpers as private static methods on the MapperClass

`EmitCycleSafeMapPair` stays the public-entry emitter (it produces the `Map(src)` + `Map(src, tracker)` pair). `ResolveCycleSafeExpression` grows a new branch:

```
Case: reference type, no explicit nested [Map<,>], has parameterless ctor
  → emit: srcExpr is null ? null! : __CloneCycleSafe_T(srcExpr, tracker)
```

Per-type helpers live as private static methods on the MapperClass with mangled prefix `__CloneCycleSafe_<TypeNameMangle>` — collision-proof, debuggable in stack traces. A new gen-time pass (in `MapEmitter` or a new sibling helper) collects the unique set of reachable types across **all** `[Map(DeepClone+CycleSafe)]` declarations in the MapperClass and emits one shared helper per type.

Helper body shape:

```csharp
private static T __CloneCycleSafe_T(T src, IDictionary<object, object> tracker)
{
    if (tracker.TryGetValue(src, out var __cached)) return (T)__cached;
    var __new = new T();
    tracker.Add(src, __new);
    __new.Prop1 = /* literal-walk or recurse via another __CloneCycleSafe_X */;
    __new.Prop2 = /* ... */;
    return __new;
}
```

Collections of literal-walked types:

```csharp
srcExpr is null
  ? null!
  : ToArray(Enumerable.Select(srcExpr, x => x is null ? null! : __CloneCycleSafe_T(x, tracker)))
```

(or `ToList(...)` depending on `dstColl.CollectionKind`, mirroring the existing `ResolveCycleSafeExpression` collection branch).

**Considered and rejected:**

- **Nested private static class `__Cloners` containing all helpers.** Tidier namespace; one extra layer of indirection in emitted code; no functional advantage over the prefix-mangled approach.
- **Per-declaration helpers (no dedup).** Simpler emit but bloats output if the user has many `[Map(DeepClone+CycleSafe)]` declarations that overlap on intermediate types. A type's clone semantics are identical regardless of which top-level `[Map<,>]` triggered it — sharing is correct and economical.

### D-4: graph-walk + dedup pass

Single gen-time pass per MapperClass, run once before `EmitCycleSafeMapPair` per declaration:

1. For each `[Map(DeepClone=true, CycleSafe=true)]` declaration in the class, walk the destination type's reachable graph (reference-typed properties + collection elements; stop at value-types/strings/explicit-nested-mapped types).
2. Track visiting stack for cycle detection.
3. For each reachable type encountered:
   - If has parameterless ctor → add to the shared "needs helper" set.
   - If primary-ctor-only AND part of a cycle (revisited via the visiting stack) → record a `ZAMP021` diagnostic against the originating declaration.
   - If primary-ctor-only AND no cycle → mark for inline emit (no helper needed).
4. After walking all declarations, emit one helper per type in the dedup set.

The walk shares its visited-type set across declarations to avoid quadratic blowup on graphs with many overlapping reachable types.

### Behavior changes (user-visible)

| Scenario                                                        | Pre-v1.5 (v1.4 behavior)             | Post-v1.5                                                          |
| --------------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------ |
| `[Map(DeepClone+CycleSafe)]`, ref-typed prop, no nested `[Map]` | Aliased (NOT cloned)                 | Cloned via emitted `__CloneCycleSafe_T` helper                     |
| Same as above, cycle through a record type                      | Aliased (silently)                   | `ZAMP021` at compile time                                          |
| Same as above, no cycle, record type                            | Aliased                              | Cloned inline via `new T(arg1: ..., arg2: ...)` (no tracker entry) |
| `[Map(DeepClone)]` solo                                         | Literal-walked (existing behavior)   | Identical — no change                                              |
| `[Map(CycleSafe)]` solo                                         | Tracker-threaded (existing behavior) | Identical — no change                                              |

Solo paths byte-identical (verified by snapshot regeneration).

## Out of scope (deferred to follow-ups)

- **`[CycleSafeIgnore]` property attribute.** Pruning attributes to skip parts of the graph. YAGNI — users with massive auto-walked graphs can declare explicit nested `[Map<X,Y>]` to opt out of the literal walk for those branches.
- **Tracker pooling.** Single tracker per top-level `Map(src)` call; reuse across the chain is already the behaviour. Pooling across calls adds complexity; defer until a concrete consumer surfaces the allocation cost.
- **Typed tracker (`Dictionary<TKey, TValue>` instead of `IDictionary<object, object>`).** Current `ReferenceEqualityComparer.Instance` keying works across mixed types in a single tracker; typing would require multiple trackers or a generic tracker per type pair. Not worth the complexity now.

## Backward compatibility

Strictly additive runtime behavior. Existing `CycleSafe`-only and `DeepClone`-only paths are byte-identical (snapshot-verified). The combined path goes from "silently aliases" to "actually clones cyclically" — a semantic change, but in line with the documented intent before the v1.4 C-1 docs alignment and what users would expect from the flag combination.

SemVer: lands as a `feat:` commit; release-please bumps Mapping minor (v1.4 → v1.5). One new diagnostic (`ZAMP021`) is added — appears only when the user opts into both flags AND the graph has a cycle through a primary-ctor-only type, so existing consumers are unaffected.
